# 검색 품질 개선 이슈

## 1. 문제현상

- "휴가 정책 알려줘"라고 질문했을 때 **"휴가 정책"** 문서가 검색 상위에 노출되지 않음
- 검색 결과 상위에 "출장 규정", "신입사원 온보딩 가이드" 등 관련성 낮은 문서가 먼저 나옴
- Relevance Score가 **0.3~0.4** 수준으로 전반적으로 낮음 (정상: 0.7 이상 기대)
- LLM이 "문서에서 해당 정보를 찾을 수 없습니다"라고 잘못된 답변을 반환

## 2. 문제원인

### 2.1 제목에 대한 가중치 부재
- 현재 임베딩 시 `제목\n본문` 형태로 단순 결합만 하고 있음
- 제목은 문서의 핵심 키워드를 담고 있지만, 긴 본문에 희석되어 벡터에 미치는 영향이 미미함
- 사용자 질문은 보통 제목 수준의 키워드를 포함하므로, 제목 가중치가 없으면 매칭 정확도가 떨어짐

### 2.2 카테고리/메타데이터 미활용
- Confluence 문서는 Space, Label 등 구조화된 메타데이터를 가짐
- 현재 이 정보가 임베딩에 반영되지 않아 문맥 파악이 어려움
- "정책" 카테고리 문서끼리의 관련성을 활용하지 못함

### 2.3 단일 벡터 검색의 한계
- 현재 벡터 유사도만으로 검색 순위 결정
- 제목/카테고리/본문 각각의 중요도를 고려하지 않음

## 3. 수정방향

### 3.1 Indexer 수정: 구조화된 임베딩 텍스트 생성

```
[제목] 휴가 정책
[카테고리] 인사/복리후생
[본문] 연차휴가 연차휴가는 근속연수에 따라...
```

- 제목, 카테고리, 본문을 명시적 태그와 함께 결합
- 제목을 **2~3회 반복**하여 벡터에서 제목의 영향력 강화
- Confluence에서 Label/Space 정보를 카테고리로 활용

### 3.2 검색 시 가중치 적용 (Weighted Hybrid Search)

| 요소 | 가중치 | 설명 |
|------|--------|------|
| 제목 매칭 | 0.5 | 제목에 쿼리 키워드 포함 시 높은 점수 |
| 카테고리 매칭 | 0.3 | 같은 카테고리 문서 우선 |
| 본문 벡터 유사도 | 0.2 | 기존 코사인 유사도 |

**구현 방안:**
1. **방안 A (간단)**: 제목을 별도 컬럼에 저장 → 검색 시 제목 키워드 매칭 점수를 벡터 점수에 가산
2. **방안 B (정교)**: 제목/카테고리/본문 각각 별도 임베딩 → 가중합으로 최종 점수 산출

### 3.3 예상 효과

- "휴가 정책" 검색 시 해당 문서가 Top 1으로 노출
- Relevance Score 0.7 이상 달성
- 사용자 질문에 정확한 답변 제공
